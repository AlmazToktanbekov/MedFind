### 3.1. Назначение разработки

Спроектировать и реализовать кроссплатформенное мобильное приложение и серверную часть для соединения пациентов Кыргызской Республики с врачами, клиниками и аптеками. Система должна:
- предоставить пациентам единую точку поиска медицинских услуг;
- дать клиникам и аптекам B2B-инструмент управления присутствием и врачебным составом;
- обеспечить устойчивую бизнес-модель B2B2C с подписками и кошельком;
- собирать обезличенную аналитику для Premium-отчётов клиникам и аптекам;
- быть готовой к подключению реальных SMS- и платёжных провайдеров (Nikita.kg, SMS.kg, Mbank Business API).

### 3.2. Функциональные требования

**3.2.1. Аутентификация и регистрация**
- Регистрация по номеру телефона с подтверждением через одноразовый код (OTP).
- Восстановление пароля: `POST /auth/password/forgot` (отправка OTP, ответ обезличен ради приватности) и `POST /auth/password/reset` (валидация OTP, ротация refresh-токена, автологин).
- JWT-аутентификация: access + refresh; автоматический рефреш при 401, очередь повторных запросов в Dio-интерцепторе.
- Хранение токенов и идентификационных данных в защищённом хранилище устройства (`flutter_secure_storage`).
- Режим `DEV_MODE`: возврат `dev_code` в теле ответа для разработки без реальной отправки SMS.
- Единая точка отправки SMS — `app/services/sms.py` (заглушка для DEV, готова к подключению Nikita.kg / SMS.kg).

**3.2.2. Роли пользователей**
- Пациент (`patient`) — основной пользователь, доступ к каталогу и избранному, бесплатно.
- Врач (`doctor`) — личный кабинет, профиль, привязка к одной клинике, всегда бесплатно.
- Клиника (`clinic`) — управление профилем, врачами, тарифом.
- Аптечная компания (`pharmacy`) — управление компанией и филиалами, тарифом.
- Администратор (`admin`) — веб-панель модерации платформы.

**3.2.3. Каталог врачей**
- Просмотр карточек, фильтрация по специализации, формату консультации (очно / онлайн / оба), цене, рейтингу, языку приёма.
- Публичный профиль врача: фото, ФИО, специализация, образование, стаж, услуги с ценами, контакты (телефон, WhatsApp, Telegram, Instagram), график приёма, рейтинг и отзывы, блок «✅ Подтверждён клиникой».
- Только врачи со статусом `active` доступны пациентам.

**3.2.4. Каталог клиник**
- Просмотр клиник, поиск и фильтрация по категориям/направлениям.
- Публичный профиль клиники: данные, контакты, фото, координаты, список подтверждённых врачей, сгруппированных по специализациям, отзывы, кнопка маршрута.
- Личный кабинет клиники: разделы «О клинике», «Контакты», «Фото», «Врачи», «Управление врачами» (заявки), «Отзывы».
- 3-шаговая регистрация клиники, моментальная активация без модерации.

**3.2.5. Каталог аптек**
- Архитектура «компания + филиалы»: таблицы `pharmacy_companies` и `pharmacy_branches`, отдельная таблица `pharmacy_branch_photos` для галереи каждого филиала.
- Публичный профиль компании: логотип, название, главный номер, сайт, описание, список активных филиалов.
- Карточка филиала: адрес, телефон, график, галерея, расстояние до пользователя, кнопки «Позвонить» и «Маршрут».
- Эндпоинт ближайших филиалов: `GET /pharmacy-branches/nearby?lat=...&lon=...` с сортировкой по расстоянию (формула Haversine).
- Геолокация запрашивается при первом входе в раздел аптек или нажатии «Ближайшие».
- Отзывы оставляются на каждый филиал отдельно (`target_type = "pharmacy_branch"`).

**3.2.6. Управление врачами клиникой**
- Заявка врача на привязку → статус `pending`.
- Подтверждение клиникой → `active`; отказ → `rejected`; деактивация → `deactivated`; удаление → `removed`.
- При `removed` врач не виден пациентам, в его личном кабинете отображается красная плашка «⚠️ Вас не видят пациенты — выберите новую клинику» с переходом на шаг выбора клиники.
- Push-уведомления врачу о решениях клиники.

**3.2.7. Регистрация врача (7 шагов)**
1. Основная информация (фото, ФИО, телефон).
2. Специализация, формат консультации (очно / онлайн / оба) и цены.
3. Образование и стаж.
4. Услуги (название + цена).
5. Контакты (WhatsApp, Telegram, Instagram).
6. График приёма (адрес автоматически берётся из выбранной клиники).
7. Выбор клиники → отправка заявки → `PendingReviewScreen`.

**3.2.8. Карты и навигация**
- Кнопка «Маршрут»: приоритетно открывает 2GIS (`dgis://2gis.ru/routeSearch/to/<lat>,<lon>`), при отсутствии установленного приложения — фоллбэк на Google Maps (`https://maps.google.com/?q=<lat>,<lon>`).
- Реализация через `url_launcher` с проверкой `canLaunchUrl`.

**3.2.9. Онлайн-консультация**
- Только через WhatsApp (`https://wa.me/<номер>`) или Telegram (`https://t.me/<username>`) — видеозвонок внутри приложения не реализуется.

**3.2.10. Избранное**
- Хранится локально в `SharedPreferences` по ключам вида `"doctor:123"`, `"clinic:456"`.
- С бэкендом не синхронизируется.

**3.2.11. Отзывы и рейтинги**
- Универсальная таблица `reviews` с полями `target_type`, `target_id`.
- Возможны жалобы (раздел админ-панели).

**3.2.12. Монетизация (B2B2C)**
- Тарифы (одинаковы для клиник и аптек): Free / Pro $20 в мес. ($200 в год) / Premium $40 в мес. ($400 в год). Скидка года — 2 месяца в подарок.
- Лимиты Free: клиника — 4 активных врача, аптека — 9 активных филиалов.
- Триал: 30 дней Pro бесплатно при регистрации клиники/аптеки, без карты, выдаётся однократно на пользователя.
- Превышение лимита блокируется на бэкенде (HTTP 402), mobile показывает модалку `PlanLimitReachedDialog` с тарифами.
- Истечение подписки: первые N (4 врача / 9 филиалов) остаются активными по `created_at ASC`, остальные деактивируются; клинике/аптеке отправляется push.
- Валюта в БД и бизнес-логике — USD; в личном кабинете отображается в KGS по текущему курсу.

**3.2.13. Кошелёк B2B-счёта**
- У каждой клиники/аптеки — кошелёк в USD.
- Пополнение по уникальному коду формата `MEDF-31-A7K4`: создаётся `WalletTransaction(type=topup, status=pending)`, пользователь видит реквизиты MedFind и копирует код в назначение платежа.
- Подтверждение — по стратегии `WALLET_CONFIRM_STRATEGY`: `"manual"` (админ в `/panel/wallet/topups` сверяет с банковской выпиской и подтверждает) или `"mbank_auto"` (webhook `POST /wallet/webhook/mbank`, заглушка возвращает 501 при manual-стратегии).
- Атомарное зачисление: SELECT FOR UPDATE.
- Покупка подписки: `POST /wallet/me/purchase {plan, period}` — атомарная транзакция (проверка баланса → списание → активация подписки через `subscription_service.set_plan_manual`); при нехватке средств HTTP 402 + код `insufficient_funds`.
- Лимиты: `WALLET_MIN_TOPUP_USD = 10`, `WALLET_MAX_TOPUP_USD = 1000`. Одновременно допускается только одна `pending`-заявка (HTTP 409 `pending_request_exists`).
- Подписки не автопродлеваются.

**3.2.14. Аналитика и Premium-отчёты**
- Таблица `analytics_events`: `event_type`, `target_type`, `target_id`, `clinic_id`, `user_id?`, `metadata`, `created_at`.
- События с mobile: `view_clinic`, `view_doctor`, `view_pharmacy_branch`, `click_call`, `click_whatsapp`, `click_telegram`, `click_route`, `add_favorite`, `search` — отправка батчем через `POST /analytics/track`.
- Отчёт клиники (10 метрик): просмотры профиля; просмотры каждого врача; звонки; переходы в WhatsApp/Telegram; нажатия «Маршрут»; добавления в избранное; средний рейтинг и число отзывов; топ врачей; график активности по дням.
- Отчёт аптеки — только по выбранному филиалу.
- Период — кастомный date picker; по умолчанию последние 30 дней.
- Этический фильтр: имена и телефоны пациентов клинике не передаются.
- Grace period: после окончания Premium отчёты доступны ещё 30 дней (`PREMIUM_REPORTS_RETENTION_DAYS = 30`). События продолжают собираться в фоне.
- Графики — `fl_chart`.

**3.2.15. Веб-панель администратора (`/panel/*`)**
Доступ по cookie + JWT. Темплейты Jinja2 (`app/templates/admin/`). 11 разделов:
1. Дашборд (регистрации, DAU, выручка, жалобы, истекающие подписки).
2. Пользователи (фильтры, блокировка, сброс пароля, история действий).
3. Клиники (фильтр по тарифу, ручное управление подпиской, заморозка).
4. Аптеки (компании + их филиалы).
5. Врачи (статусы, принудительное изменение).
6. Отзывы и жалобы (модерация).
7. Контент (статьи «Первая помощь», справочники симптомов/специализаций/категорий).
8. Финансы (платежи, выручка, провалившиеся транзакции).
9. Аналитика платформы (DAU/WAU/MAU, топ-запросы, география).
10. Push-рассылки (сегментация по роли / городу / плану, шаблоны, история).
11. Логи действий админов (аудит, не удаляется).

**3.2.16. Автоматизация (APScheduler, ежедневно 09:00)**
- Напоминания о подписке за 7, 3 и 1 день до окончания + в день окончания.
- Автоматическая деактивация лишних врачей/филиалов при истечении Pro/Premium.
- Автоотмена pending-заявок старше 7 дней.
- Заглушка предупреждений по жалобам (`COMPLAINTS_WARNING_THRESHOLD = 100`, `COMPLAINTS_WINDOW_DAYS = 10`).

**3.2.17. Загрузка файлов**
- `POST /upload/photo` — сохранение в локальную папку `uploads/`, возврат URL `/uploads/<filename>`.
- В конфигурации зарезервированы ключи S3 (миграция на S3 — задел развития).

**3.2.18. Локализация интерфейса**
- 3 языка: русский, кыргызский (код `ky`), английский.
- Базовый язык — русский (хардкод в текущей итерации); запланирован переход на `flutter_localizations` с файлами `app_ru.arb`, `app_ky.arb`, `app_en.arb`.
- Выбор языка хранится в `SharedPreferences` (ключ `app_locale`).

- Единый стиль иконок: пакет `phosphor_flutter`, стиль Outline.

### 3.4. Архитектурные требования

**Backend (FastAPI):**
- Async SQLAlchemy с драйвером `asyncpg`; сессия через `Depends(get_db)` в каждом роутере.
- Pydantic-схемы: разделение схем чтения (`DoctorOut`, `DoctorListItem`) и записи (`DoctorCreate`, `DoctorUpdate`).
- Все роутеры подключаются в `app/main.py` через `include_router`.
- Конфигурация — `app/core/config.py` (pydantic-settings, чтение из `.env`).
- Роутеры: `auth`, `doctors`, `clinics`, `pharmacies`, `reviews`, `search`, `content`, `admin`, `upload`, `panel`, `wallet`, `subscriptions`, `analytics`.
- Миграции БД — Alembic (`alembic upgrade head`, `alembic revision --autogenerate`).
- Сидинг тестовых данных — `python -m app.services.seed`.

**Frontend (Flutter):**
- Структура feature-first: каждая фича в `mobile/lib/features/<name>/` содержит слои `data/` (Repository, HTTP через `ApiClient().dio`), `providers/` (StateNotifierProvider, бизнес-логика), `presentation/screens/` (виджеты, чтение через `ref.watch`/`ref.read`).
- Папка `domain/` зарезервирована, в текущей итерации пуста.
- Фичи: `auth`, `clinics`, `doctors`, `health`, `home`, `pharmacies`, `profile`, `provider`, `search`.
- Riverpod — классический (`StateNotifierProvider`, `Provider`), без `riverpod_generator`.
- `ApiClient` — настоящий singleton (приватный конструктор `_internal()` + factory).
- Роутинг — `GoRouter`, начальный маршрут `/splash`.
- `MainScreen` — `IndexedStack` с 4 табами: Home / Search / Health / Profile; вложенные маршруты открываются поверх.
- Кодогенерация (freezed) — `dart run build_runner build --delete-conflicting-outputs`.
- Канонические списки симптомов, специализаций, категорий клиник — `core/constants/app_constants.dart`, без дублирования.
