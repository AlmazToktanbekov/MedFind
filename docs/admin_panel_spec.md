# Детальная спецификация веб-панели администратора MedFind

> Документ описывает, **как должна работать** админ-панель: источники данных, отображаемая
> информация, вычисления и действия управления. Платформа бесплатная — финансовых разделов нет.

## Общие принципы работы

- Панель доступна по `/panel/*`, рендерится на сервере (Jinja2).
- Вход — по тем же учётным данным, роль `admin`. Маркер JWT хранится в cookie браузера.
- Каждый запрос страницы проверяет cookie и роль; иначе — редирект на `/panel/login`.
- Каждое изменяющее действие администратора записывается в таблицу `admin_logs`
  (кто, что, над каким объектом, когда, IP) — для аудита.
- Админ не редактирует чужой контент и не подтверждает регистрации: он только
  наблюдает, блокирует и модерирует.

## Раздел 1. Дашборд `/panel/`

**Источник данных:** `users`, `doctors`, `clinics`, `pharmacy_companies`, `pharmacy_branches`, `complaints`.

**Отображаемая информация (карточки):**
- Всего пользователей; новых за сегодня / 7 дней / 30 дней — `COUNT(users)` с фильтром по `created_at`.
- Разбивка пользователей по ролям — `COUNT(users) GROUP BY role`.
- DAU / WAU / MAU — `COUNT(users)` где `last_active_at` за 1 / 7 / 30 дней.
- Размер каталога — `COUNT` активных врачей, клиник, аптечных компаний и филиалов.
- Врачей в статусе `pending` — счётчик, ведёт в раздел врачей с фильтром.
- Новых жалоб (`status = new`) — счётчик, выделен, ведёт в раздел жалоб.

**Графики:** регистрации по дням за 30 дней; активность пользователей по дням.

**Действия:** только переходы в разделы (быстрые ссылки на жалобы и заявки).

## Раздел 2. Пользователи `/panel/users`

**Источник данных:** `users`; карточка — связанные `doctors` / `clinics` / `pharmacy_companies`, `admin_logs`.

**Список:** ID, ФИО, телефон, email, роль, город, дата регистрации, статус, последняя активность.
**Фильтры:** по роли, по статусу (активен / заблокирован / удалён); поиск по телефону и имени.

**Карточка пользователя `/panel/users/{id}`:** профиль + история действий пользователя.

**Действия управления:**
- **Заблокировать** → `users.is_active = false`; пользователь не может войти. Запись в `admin_logs`.
- **Разблокировать** → `users.is_active = true`.
- **Сбросить пароль** → `users.must_change_password = true`; при следующем входе требуется смена.
- **Удалить аккаунт** (мягко) → `users.deleted_at = now()`; учётная запись скрывается.

## Раздел 3. Врачи `/panel/doctors`

**Источник данных:** `doctors`, связанные `clinics`, `reviews`, `complaints`.

**Список:** ФИО, специализация, клиника, статус (`pending` / `active` / `rejected` / `deactivated` / `removed`), рейтинг, число отзывов, дата.
**Фильтры:** по статусу, специализации, клинике.
**Карточка `/panel/doctors/{id}`:** полный профиль (образование, стаж, услуги, контакты, график), отзывы, жалобы на врача.

**Статистика:** число врачей по каждому статусу; топ специализаций; средний рейтинг.

**Действия управления (только при жалобах):**
- **Заморозить** → перевод в статус `deactivated`; врач скрыт из публичного каталога.
- **Принудительно изменить статус** → допускается только при наличии жалоб.
- Редактирование профиля врача администратору **недоступно**.

---

## Раздел 4. Клиники `/panel/clinics`

**Источник данных:** `clinics`, связанные `doctors`, `reviews`, `complaints`.

**Список:** название, категории, адрес, телефон, число врачей, рейтинг, статус (активна / заморожена).
**Карточка `/panel/clinics/{id}`:** профиль клиники, список её врачей по специализациям, отзывы, жалобы.

**Действия управления:**
- **Заморозить** → `clinics.is_frozen = true`, `frozen_reason` обязателен; клиника скрыта.
- **Разморозить** → `clinics.is_frozen = false`.

---

## Раздел 5. Аптеки `/panel/pharmacies`

**Источник данных:** `pharmacy_companies`, `pharmacy_branches`, `reviews`, `complaints`.

**Список:** название сети, число филиалов, телефон, статус.
**Карточка `/panel/pharmacies/{id}`:** профиль компании + список всех филиалов с адресами и режимом работы.

**Действия управления:**
- **Заморозить / разморозить** компанию → `pharmacy_companies.is_frozen`.

---

## Раздел 6. Отзывы и жалобы `/panel/complaints`, `/panel/reviews`

**Источник данных:** `complaints`, `reviews`, `users` (авторы), цели жалоб.

**Вкладка «Жалобы»** (приоритетная, открывается первой):
- Список: на кого жалоба (тип + объект), причина, кто подал, дата, статус (`new` / `resolved`); новые сверху.
- Агрегаты: число жалоб по каждому объекту; подсветка при достижении порогов 10 / 100 / 300.
- Действия: **рассмотреть** (→ `status = resolved`, `resolution_note`), **принять меры**
  (заблокировать/заморозить цель), **отклонить** жалобу.

**Вкладка «Отзывы»:**
- Список всех отзывов; фильтр по рейтингу и типу объекта.
- Действие: **удалить недопустимый отзыв** → удаление записи `reviews` + пересчёт рейтинга объекта + обязательная причина в `admin_logs`.

## Раздел 7. Аналитика платформы `/panel/analytics`

**Источник данных:** `users`, `analytics_events`, `search_logs`.

**Отображаемая информация:**
- Регистрации по дням и по ролям (график).
- DAU / WAU / MAU (график).
- **Топ поисковых запросов** — `search_logs` сгруппировать по `query`, отсортировать по частоте.
- **Запросы без результатов** — `search_logs` где `results_count = 0` (чего не хватает в каталоге).
- Агрегаты событий — `analytics_events` по `event_type`: просмотры, звонки, переходы в мессенджеры, маршруты.
- Топ специализаций по спросу.

**Действия:** только просмотр (раздел аналитический, без управления).

---

## Раздел 8. Журнал действий администраторов `/panel/admin-logs`

**Источник данных:** `admin_logs`.

**Список:** администратор, действие, тип и ID объекта, дата, IP-адрес.
**Фильтры:** по администратору, типу действия, дате.
**Действия:** только просмотр. Журнал **не удаляется** — основа аудита.

---

## Раздел 9. Служебные функции `/panel/system`

**Источник данных:** планировщик APScheduler.

**Отображаемая информация:** список регламентных задач (`complaints_warning`, `unblock_expired`),
время последнего и следующего выполнения.

**Действия управления:**
- **Запустить задачу вручную** → немедленный запуск выбранной задачи.
- **Тестовое push-уведомление** → проверка работы Firebase Cloud Messaging.

---

## Автоматические процессы (работают без участия админа)

- Ежедневно job `complaints_warning`: агрегирует жалобы; при 10 / 100 / 300 — уведомление,
  серьёзное уведомление, автоблокировка на 14 дней.
- Ежедневно job `unblock_expired`: снимает истёкшие блокировки.
